# Activities 活动原型

给产品设计新活动用的可点击原型：纯前端、假数据、不连接任何后端。基于彩票 H5（ar_v2_vue）分叉。设计文档见 [`docs/specs/2026-09-21-活动原型-设计方案.md`](./docs/specs/2026-09-21-活动原型-设计方案.md)（整体方案）和 [`docs/specs/2026-09-21-活动控制台-控制项设计.md`](./docs/specs/2026-09-21-活动控制台-控制项设计.md)（控制台与每个活动的控制项）；要 AI 改代码前，先让它看 [`AGENTS.md`](./AGENTS.md)。

## 1. 这是什么

这是一个能在浏览器里点开走查的活动原型，所有数据都是前端假造的，不请求任何真实后端。产品在这里设计新活动、调整交互，确认没问题后再交给正式项目开发。

## 2. 快速开始（产品）

环境：Node 22 LTS + pnpm 11。

```bash
npm install -g pnpm@11
git clone <新仓库地址> Activities
cd Activities
pnpm install
pnpm dev
```

`pnpm dev` 启动后浏览器会自动打开控制台：http://localhost:5190/console.html

## 3. 控制台怎么用

控制台分三栏：

- **左栏清单**：按“活动类型 / 入口页 / 其他活动”分组列出全部活动，分组标题右侧是该组条目数。点一项，手机按当前参数重新打开对应页面或弹窗；标题前的蓝点表示这个活动的参数被调整过。
- **中栏手机**：H5 实时预览，视口固定 375×812。
- **右栏面板**：当前活动自己的控制项，自上而下是：
  - **边界场景**：一键切到某个典型状态（如“今日已签到”“次数用完”“剩 30 秒结束”），没写到的参数回到默认值；当前参数和哪个场景一致，那个按钮就高亮。
  - **参数**：逐项调整（开关、下拉、数字、倒计时），改完手机原地重新加载；倒计时刷新页面后接着走，不会重置。
  - **动作**：打开相关页面或弹出弹窗（弹窗每次都能再弹出来）。
  - 右上角“恢复默认”按钮只恢复这一个活动的参数；想重新打开页面，直接再点一次左栏清单项。
- **顶部工具栏**：已登录、语言（中文 / English / हिंदी）、接口延迟、重置数据（清空全部会话数据并恢复默认，手机回到首页）。
- 窗口窄于 1280px 时，左栏收进工具栏最左侧的“清单”按钮。
- 在 PC 上直接打开 `index.html` 会自动跳转到控制台；想看不带控制台的纯 H5 页面，访问 `index.html?h5=1`。

页面请求了、但假数据还没处理的接口，会在浏览器控制台打印 `[mock] 未覆盖: <接口路径>` 警告。

每个活动有哪些参数和边界场景，写在 `entrance/prototype/public/catalog.json` 的 `activities` 里；想加一个控制项，改这里的声明，再在对应的假数据文件里用 `params()` 读取即可，不用改控制台代码（规则见 `AGENTS.md` 第 16 条）。

## 4. 加一个新设计

- 已有页面结构、只是改活动内容的：把需求交给 AI，照 [`AGENTS.md`](./AGENTS.md) 的规则改 Vue 页面和假数据。
- 全新样式、还没定稿的：复制 `entrance/prototype/public/prototypes/_example` 目录改名，写成独立 HTML 页面，再在 `catalog.json` 的 `groups` 里新增一个“新设计”分组登记（清单默认没有这一组）。

## 5. 运维部署

纯静态站点：`pnpm install --frozen-lockfile && pnpm build`，把 `dist/` 整个目录放到任意静态服务器上。环境要求、缓存设置、Nginx 示例、发版、冒烟检查与回滚见 [`docs/运维部署说明.md`](./docs/运维部署说明.md)。

仓库：https://github.com/superalexwake/ar_v3_ActivtiesDesign （公开，只维护 `master` 分支）。禁止 `git push --all` 或 `git push --mirror`。

## 6. 跟进线上版本

基线：`ar_v2_vue masterBranch/main-3.10@be179c89f`；另含从 `upstream/uat@454bad727` 整体移植的周卡月卡（35 个文件，内容与 uat 完全一致，清单见设计文档）。

线上发版后，按设计文档 §9.4 的补丁流程同步：在另一个 ar_v2_vue 克隆里对 `src/` 目录生成从基线到新发版的补丁文件（`git diff --binary`），在本仓库里应用（`git apply --3way`），走查确认无误后，把上面这行基线更新成新的提交。
