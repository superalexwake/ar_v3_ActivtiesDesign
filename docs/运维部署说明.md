# 活动原型 · 运维部署说明

| 项 | 内容 |
|---|---|
| 仓库 | https://github.com/superalexwake/ar_v3_ActivtiesDesign （公开），部署分支 `master` |
| 性质 | 纯静态站点：没有后端服务、没有数据库、不需要环境变量和密钥 |
| 访问对象 | 产品、设计等内部人员（PC 看控制台，手机看 H5） |
| 最后核对 | 2026-09-22 |

## 1. 这是什么

给产品设计活动用的可点击原型，由彩票 H5 派生。页面里的数据全部由前端假数据生成，运行时**不会请求任何真实后端**：接口域名固定为 `https://prototype.invalid`（保留域名，无法解析），所有接口请求在浏览器内被拦截并返回假数据。

构建产物只包含原型入口（`entrance/prototype`）。仓库里 `entrance/` 下其他租户目录不参与构建，产物中没有它们的域名、Firebase、GA 等配置（已核对：产物里的接口域名只有 `prototype.invalid`，没有任何密钥或统计 ID）。

## 2. 构建

### 2.1 环境

| 项 | 要求 |
|---|---|
| Node | 22 LTS（仓库 `.nvmrc` 为 22；Vite 7 最低要求 Node ≥ 20.19） |
| pnpm | 11（`package.json` 的 `packageManager` 为 `pnpm@11.17.0`） |
| 网络 | 安装依赖需要访问 npm 源；构建本身不需要网络 |

安装 pnpm（任选其一）：

```bash
corepack enable && corepack prepare pnpm@11.17.0 --activate
```

```bash
npm install -g pnpm@11
```

### 2.2 命令

```bash
pnpm install --frozen-lockfile && pnpm build
```

- `pnpm build` 实际执行 `cross-env NODE_ENV=prototype vite build --mode prototype`，本地约 11 秒。
- 产物目录 `dist/`，约 38 MB、1,400 多个文件，要**整个目录**部署：

| 路径 | 说明 | 文件名带 hash |
|---|---|---|
| `index.html` | H5 入口（手机访问） | 否 |
| `console.html` | PC 控制台入口 | 否 |
| `catalog.json` | 控制台清单与各活动的控制项，H5 启动时也会读取 | 否 |
| `data.json` | 全局加载动画 | 否 |
| `assets/` | JS、CSS、字体、图片 | 是 |
| `mock-img/` | 假数据用的图片（Banner、渠道图标等） | 否 |
| `prototypes/` | 产品独立 HTML 原型 | 否 |
| `favico.ico`、`icon-*.png`、`indexh.css` | 图标与样式 | 否 |

## 3. 部署

### 3.1 服务器与路径

- 任意静态文件服务都可以（Nginx、OSS + CDN、Cloudflare Pages 等），不需要 Node 运行时。
- **推荐用独立子域名的根路径**，例如 `https://activities-proto.<公司域名>/`。放在子路径（如 `/proto/`）也能正常使用，但全局加载动画会缺失：加载动画组件用绝对路径 `/data.json` 取文件。
- 路由是 hash 模式（`#/...`），**不需要**任何回退或重写规则。
- 默认首页为 `index.html`。

### 3.2 入口地址

| 地址 | 效果 |
|---|---|
| `/`、`/index.html` | 手机上直接显示 H5；PC 上（窗口宽 ≥ 900px）自动跳转到控制台 |
| `/console.html` | PC 控制台（三栏：活动清单 | 手机预览 | 活动控制面板）；窗口窄于 900px 时跳转到 H5 |
| `/index.html?h5=1` | PC 上强制看纯 H5，不跳转控制台 |

### 3.3 缓存策略（必须设置）

没有 hash 的文件一旦被浏览器或 CDN 缓存，发版后用户会一直看到旧版本（验收时出现过）。按下表设置：

| 路径 | Cache-Control |
|---|---|
| `*.html`、`catalog.json`、`data.json` | `no-cache` |
| `mock-img/*`、`prototypes/*` | `no-cache`（产品会改这里的文件） |
| `assets/*` | `public, max-age=31536000, immutable` |
| 图标类（`favico.ico`、`icon-*.png`、`indexh.css`） | `max-age=3600` 或 `no-cache` |

### 3.4 Nginx 配置示例

```nginx
server {
    listen 80;
    server_name activities-proto.example.com;
    root /var/www/activities-proto;   # dist/ 目录里的内容
    index index.html;

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;

    # 内部原型，不让搜索引擎收录（页面里已有 noindex，再加一层响应头）
    add_header X-Robots-Tag "noindex, nofollow" always;

    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
        add_header X-Robots-Tag "noindex, nofollow" always;
        try_files $uri =404;
    }

    location / {
        add_header Cache-Control "no-cache";
        add_header X-Robots-Tag "noindex, nofollow" always;
        try_files $uri =404;
    }
}
```

### 3.5 OSS + CDN（与 WinGo 原型同一套时）

1. 把 `dist/` 里的全部内容上传到桶的目标目录（覆盖同名文件）。
2. 按 3.3 设置对象的 `Cache-Control` 元数据；CDN 规则里让 `*.html`、`*.json`、`mock-img/*` 回源校验或不缓存。
3. 发版后刷新 CDN 上的 `*.html`、`catalog.json`、`data.json`、`mock-img/*`。`assets/` 文件名带 hash，不需要刷新。

## 4. 访问控制与安全

- 页面已带 `<meta name="robots" content="noindex,nofollow">`；建议同时按 3.4 加 `X-Robots-Tag` 响应头。
- 原型里没有真实用户数据、没有账号密码、不连接真实接口，但属于内部设计资料，**建议限制为内部访问**（IP 白名单、Basic Auth 或 Cloudflare Access 等，由运维按现有规范选择）。
- 站点不需要写权限，只读静态文件即可。

## 5. 发版流程

1. 拉取最新代码并记下版本：
   ```bash
   git pull origin master
   ```
   ```bash
   git rev-parse --short HEAD
   ```
2. 构建：`pnpm install --frozen-lockfile && pnpm build`。
3. 上传 `dist/` 的全部内容（覆盖）。旧的 `assets/` 文件可以保留，不影响新版本；需要清理时定期删除即可。
4. 如有 CDN，按 3.5 刷新无 hash 的文件。
5. 按第 6 节冒烟检查。

## 6. 冒烟检查

1. PC 打开 `/console.html`（窗口宽 1280px 以上）：看到三栏布局；顶部工具栏显示的构建时间和 `commitId` 与本次发版版本一致。
2. 左栏任点 3 项，例如“回归新充值奖励”（出现弹窗和倒计时）、“每日签到”、“积分商城”：中间手机正常显示页面。
3. 打开浏览器开发者工具的 Network：只有本站点的静态资源请求，没有对外部接口域名的请求。
4. 手机打开 `/`：直接显示 H5 首页。
5. 右上角“重置数据”可以恢复初始状态（只影响当前浏览器标签页）。

## 7. 回滚

- 保留最近几次的 `dist/` 压缩包，回滚时重新上传上一版即可。
- 或者检出上一个版本重新构建：
  ```bash
  git checkout <上一版本的提交号>
  ```
  ```bash
  pnpm install --frozen-lockfile && pnpm build
  ```

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 发版后看到的还是旧页面 | `*.html` 或 `catalog.json` 被浏览器 / CDN 缓存，按 3.3 设置并刷新 CDN |
| 页面空白，Network 里 `assets/` 返回 404 | 上传目录层级不对：要部署 `dist/` 里面的内容，入口地址跟着部署目录走 |
| 页面能用但没有全局加载动画 | 部署在子路径下（见 3.1），换成子域名根路径即可 |
| `pnpm build` 报 Node 版本不满足 | 换 Node 22（最低 20.19） |
| `pnpm install --frozen-lockfile` 失败 | pnpm 版本不对，用 pnpm 11（见 2.1） |
| PC 打开 `/console.html` 跳到了手机页面 | 浏览器窗口窄于 900px，放大窗口即可（设计如此） |
