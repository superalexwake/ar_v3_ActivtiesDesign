## 1. 目的与背景

### 1.1 问题

产品需要在现有 H5 活动的基础上设计新方案。彩票 H5（ar_v2_vue）的活动页依赖后端接口和登录态，离开测试环境和测试账号就无法展示，产品也没办法在上面叠加新设计。

本项目把 ar_v2_vue 派生为独立的 Activities 仓库：保留线上真实页面代码，用前端假数据替代后端，并提供一个 PC 演示控制台。产品在控制台里一键打开任意活动，也能把新设计（Vue 页面或独立 HTML）放进同一个手机框里展示。

### 1.2 权威来源

| 内容 | 来源 |
|---|---|
| 页面代码基线 | ar_v2_vue `masterBranch/main-3.10`（当前发版线；`master` 已停更，不作为基线） |
| 21 种活动类型清单 | `Ar_V3_LottoPlatform_BackendDesign` 字段词典中的活动类账变子类型 |
| 控制台交互参考 | https://win-cn.dbdbdbtest.com/（WinGo 创新版原型：左侧手机框 + 右侧演示控制台） |
| 类型与路由的映射 | `src/hooks/useBonusPack.hook.ts`（`mapParam`）、`src/components/Activity/Section/index.vue` |

| 接口清单 | `src/api/url.ts`、`src/api/modules/*.ts`；非活动接口另见 `docs/api-usage-report.md` |

### 1.3 用户约束

- **C1** 任何修改都不影响 ar_v2_vue 仓库。
- **C2** 完成后新建独立仓库，交给运维打包部署。
- **C3** 产品拉取该仓库，用 AI 修改，并能在本地运行。

### 2.2 非目标

- 真实登录注册、充值、提现、支付：页面可以打开，数据为空或是固定假数据。
- 彩票游戏（`src/saasLottery`）与三方游戏：可以跳转，数据走兜底，不做设计还原。
- 多租户皮肤与多语言：只维护 1 套皮肤（redStyle）；语言只维护中文、英语、印地语。
- 站内信 WebSocket、Firebase 与极光推送、PWA、埋点。
- 把任何改动同步回 ar_v2_vue；自动化的上游同步工具。

## 4. 约束与假设

### 4.1 约束

- 技术栈沿用基线：Vue 3.3、Vite 7、Vant 4、Pinia、vue-router 4（hash 模式）、pnpm（lockfile v9）。
- Vite 7 要求 Node ≥ 20.19。本仓库固定 Node 22 LTS（`.nvmrc`）和 pnpm 11（`package.json` 的 `packageManager`）。
- 构建按入口目录区分租户：`NODE_ENV=<entrance 目录名>`（见 `vite.config.ts` 的 `root`、`envDir`）。构建只使用 `entrance/prototype`；其余租户入口和皮肤目录原样保留（D2），不参与构建，也不维护。
- C1 的落实：本地仓库中 ar_v2_vue 的远端已改名为 `upstream`，推送地址设为无效值，`git push upstream` 必然失败（2026-09-21 已执行并验证）。`~/work/ar_v2_vue` 不做任何操作。
- 新仓库不带 ar_v2_vue 的提交历史（D1）：本地建孤儿分支 `main`，以基线快照作为根提交，所有原型改动都提交在它上面；新仓库只推送 `main`（见 9.5）。

### 4.2 假设（任一不成立都要修改设计）

- **A1** 所有 axios 实例都在 mock 层（`entrance/prototype/mock`）安装之后才创建，由入口文件首行导入来保证。万一有实例提前创建，它的请求会发往原型专用的无效域名并失败，不会到达真实后端；走查时会表现为报错，能被发现。
- **A2** 活动页面的渲染只依赖 HTTP 数据和 localStorage，不依赖 WebSocket 推送。
- **A3** 21 种类型清单在 v1 内不变。
- **A4** 产品的独立 HTML 原型是自包含的静态文件（与 WinGo 原型同类），不需要构建。

## 5. 方案选择

| 方案 | 结论 | 理由 |
|---|---|---|
| A 沿用源码 + 前端假数据 | 采用 | 页面就是线上代码；跳转、弹窗、动画原生可用；构建产物本身就是静态文件 |
| B 手写静态 HTML（WinGo 原型的做法） | 否决 | 需要手工重写约 51 个路由页面；视觉和交互必然偏离线上；线上改版后要逐页人工同步 |
| C 按 A 运行后导出静态快照 | 否决 | 在 A 之外还要多一套导出流程；弹窗、Tab、转盘动画等交互全部丢失 |

其他已决事项（2026-09-21）：

| 编号 | 决定 | 理由 |
|---|---|---|
| D1 | 新仓库不带 ar_v2_vue 的提交历史 | 仓库体积小；历史中的旧配置和密钥不会外发给产品和运维；跟进线上版本改用 9.4 的补丁流程 |
| D2 | 保留全部租户入口和皮肤目录 | 与线上仓库结构一致，便于对照；它们不参与构建，由 `AGENTS.md` 约束 AI 只改原型相关目录 |
| D4 | 周卡月卡以 `upstream/uat` 为准整体移植（35 个文件） | uat 相对基线 `be179c89f` 的净差异只有本功能涉及的 35 个文件，其余提交内容已在基线中或已被 revert；整文件取 uat 版本等价于应用其 diff，且不产生冲突 |
| D5 | 原型支持中文、英语、印地语三语切换，假数据文案随语言切换 | 产品需要向这三类语言的用户演示；`pick(ctx, 中文, 英文, 印地语)` 只要求假数据按需三语齐写，不引入完整 i18n 词典的维护成本 |

## 6. 逻辑视图

### 6.1 模块与依赖

```
console.html（PC 演示控制台，原生 HTML/CSS/JS）
 ├─ 读取 catalog.json ─────────────────── 活动清单 + 新设计清单
 ├─ 写入 localStorage['proto:scenario'] ── 场景
 └─ iframe 手机框
      ├─► index.html（H5，Vue 应用）
      │     └─ main.ts
      │          ├─ ① import './mock'   安装假数据 adapter、写入或清除登录态、禁用 Service Worker
      │          └─ ② 业务代码（不修改）
      │                └─ 3 个 axios 实例 ──► mock adapter ──► handlers（读场景、改会话状态）
      └─► prototypes/<名称>/index.html（产品的独立 HTML 原型）
```

### 6.2 目录与职责

| 路径 | 职责 | 修改方 |

| `AGENTS.md`、`CLAUDE.md` | AI 修改规则；`CLAUDE.md` 只有一行 `@AGENTS.md` | 前端 |

原型代码全部放在 `entrance/prototype` 下，`src/` 保持与线上一致，这样按 9.4 用补丁同步线上版本时不会和原型代码冲突。

mock 层只允许导入第三方库（如 `axios`、`dayjs`）、自身文件、纯常量表 `@/api/url`，以及 `import type` 形式的类型。不能导入 `src` 下的其他运行时模块，否则会在 adapter 安装之前触发 `axios.create`，破坏假设 A1。

### 6.3 接口契约

#### 6.3.1 场景、上下文与处理函数

场景（`Scenario`）、会话状态（`SessionState`）、活动参数与处理函数上下文（`MockContext`）的类型以 `entrance/prototype/mock/types.ts` 为准，设计见《活动控制台-控制项设计》§1.1～§1.4：场景只保存登录、弹窗、延迟、各活动参数覆盖值和最近打开的活动（`focus`）；奖励状态与活动开关不再是全局开关，而是各活动在 `catalog.json` 中声明的参数，处理函数用 `params<T>(ctx, '<活动ID>')` 读取。首页弹窗键 `PopupKey` 共 7 个：`first-recharge`、`return-award`、`app-download-reward`、`re-benefit`、`coupon-arrival`、`treasure-chest`、`register-gift`。

`pick(ctx, zh, en, hd)`（`mock/i18n.ts`）按 `ctx.lang` 选取假数据文案，金额、日期、编号等非文案字段不需要翻译。`featureState(ctx, key, init)`（`mock/state.ts`）读取或初始化 `SessionState.features` 中某个功能自有的会话数据，首次访问时用 `init()` 生成初始值。`GetHomeSettings` 的 `languages` 字段固定返回 `'zh|en|hd'`。

| 维度 | 契约 |
|---|---|
| 输入 | `path` 与路由表的键精确匹配；`body` 来自业务请求，字段以 `src/api/modules/*.ts` 中的调用为准 |
| 输出 | `code: 0` 表示成功；`data` 的形状以 `src/types/api` 中的类型和模板实际读取的字段为准 |
| 错误 | 业务失败用 `fail(msg, { msgCode, data, code })` 返回：默认 `code: -2`，由现有拦截器 reject 并弹出提示；页面只处理成功分支的接口用 `code: 1`；`msg` 三语。处理函数抛出异常（含读取未声明的活动参数）时，adapter 返回 `code: -1`，并在浏览器控制台打印接口路径和异常 |
| 副作用 | 只允许修改 `ctx.state`；不得发起网络请求，不得读写业务代码使用的 localStorage 键 |
| 并发 | 浏览器单线程顺序执行；领取类处理函数按记录 ID 幂等，重复领取返回 `code: -2` |

#### 6.3.2 Adapter 分发规则

1. 取请求 URL 的 pathname，依次去掉 `/api/webapi`、`/api` 前缀，得到 `path`。
2. 路由表命中：等待 `scenario.latencyMs`，调用处理函数，包装为 `{ data: envelope, status: 200, statusText: 'OK', headers: {}, config }` 返回。
3. 路由表未命中：返回兜底信封 `{ code: 0, msg: 'Succeed', data: { list: [], totalCount: 0, totalPage: 1 } }`，把 `path` 去重后记入 `window.__protoMock.unhandled`，并输出 `console.warn('[mock] 未覆盖: ' + path)`。
4. ArUPI 支付接口（响应没有信封）和开奖 JSON（URL 以 `.json` 结尾）未命中时返回 `{}`。这两类属于非目标页面，允许显示空状态或报错。

#### 6.3.3 伪造登录态

`scenario.loggedIn === true` 时，启动阶段写入下列 localStorage 键；为 `false` 时删除这些键。

| 键 | 值 | 读取方 |
|---|---|---|
| `token` | `prototype-token` | 路由守卫、`requireLoginAction`、请求头 |
| `tokenHeader` | `Bearer ` | `src/api/http/requestBuilder.ts` |
| `refreshToken` | `prototype-refresh` | 401 刷新分支（mock 不返回 401，此键只用来防止误登出） |
| `numberType` | `91`（不带加号的区号，真实登录同样写入） | 手机号输入组件（如激活验证弹窗 `ActiveVerify.vue`） |
| `userInfo` | `session.ts` 的 `userInfoOf(ctx)`：符合 `UserInfo`（`src/types/api/interface/store/store.d.ts`）的虚构用户，与 `GetUserInfo` 同源，`useLanguage` 为当前语言 | 全站 |

H5 内的登录、登出接口也由 mock 处理，产品可以演示登录流程。控制台的登录开关是最终依据：每次重新加载时按场景重新写入或清除。

### 6.4 AI 修改规则

以仓库根目录 `AGENTS.md` 为准（运行与自检、目录地图、18 条规则）。要点：禁止接入真实接口和真实数据；`src/` 只允许 `src/plugins/html.ts` 与从 `upstream/uat` 整体移植的周卡月卡文件存在差异；handler 只改 `ctx.state`，活动数据用 `featureState(ctx, '<活动ID>', init)`，参数用 `params<T>(ctx, '<活动ID>')` 读取；用户可见文案三语。

## 7. 过程设计

### 7.1 H5 启动

1. `index.html`：PC 顶层访问时（不在 iframe 内、视口宽度 ≥ 900px、URL 不带 `h5=1`）执行 `location.replace('console.html' + location.hash)`。加 `h5=1` 可以在 PC 上直接看纯 H5，例如导入设计工具时使用。
2. `main.ts` 首行导入 `./mock`（即 `entrance/prototype/mock/index.ts`），依次执行：
   1. 读取并校验场景；
   2. `axios.defaults.adapter = mockAdapter`；
   3. 注销本站点已注册的 Service Worker，并让 `navigator.serviceWorker.register` 不再注册新的（`src/hooks/usePwa.ts` 的 `greatPwa` 会在页面 load 时尝试注册 `/ar-sw.js`）；
   4. 等待 `catalog.json` 加载并解析各活动参数（顶层 await，失败时按空清单处理）；
   5. 按 `scenario.loggedIn` 写入或清除登录态；
   6. `window.__protoMock` 提供未覆盖接口、场景和生效参数。
3. 业务模块开始求值，3 个 `axios.create()` 都继承 mock adapter。
4. `App.vue` 请求 `GetHomeSettings` 等启动接口，全部由 mock 返回。启动配置必须满足：不强制跳转 `/installApp`；不初始化 Firebase 和极光推送；不做线路测速；`isOpenBrowserConsoleDebug: true`，即不启用反调试；登录和刷新 token 的响应不带 `webSocketUrl`。

### 7.2 请求处理

业务调用 → axios 实例 → 现有请求拦截器（签名、缓存、取消重复、请求头）→ mock adapter → 现有响应拦截器（code 为 0 或 1 视为成功）→ 调用方。

接口缓存（`src/api/http/httpCache.ts`）是内存中的 Map，每次重新加载 iframe 都会清空，所以切换场景后不会读到旧数据。

### 7.3 奖励状态流转

```
各活动参数决定初始状态（可领取 / 已领取 / 已过期 / 空数据）
可领取 ──(领取接口成功)──────► 已领取（余额 += 奖励金额，写入领取键 <活动ID>:<记录ID>）
已领取 ──(再次领取)──────────► 保持已领取，返回“奖励已领取”的业务失败
任意状态 ──(改参数 / 边界场景 / 恢复默认 / 弹出弹窗)──► 清该活动的会话数据，按参数重新生成
任意状态 ──(重置数据)────────► 清空全部会话数据，恢复默认场景
```

会话状态保存在 `sessionStorage['proto:state']`：同一标签页内刷新会保留，新开标签页从初始状态开始。

### 7.4 控制台

三栏布局（左清单 | 中手机 | 右当前活动的控制面板）加顶部工具栏，手机视口固定 375×812（与 750 设计稿以及 `postcss.config.js` 的 `rootValue: 75` 一致）；各尺寸下的栏宽、面板结构和特殊状态见《活动控制台-控制项设计》第 2 节。视口宽度小于 900px 时，`console.html` 跳转到 `index.html`。

## 8. 失败与安全设计

- **真实后端隔离**：`entrance/prototype/.env` 和仓库根目录的 `.env` 中，所有接口域名（`VITE_API_URL`、`VITE_SAAS_API_URL`、`VITE_SAAS_JSON_URL`、`VITE_BAST_URL`）都设为 `https://prototype.invalid`。`.invalid` 是保留顶级域名，不会被解析。即使 adapter 没有生效，请求也到不了真实后端。
- **场景是信任边界**：`localStorage['proto:scenario']` 可能被手工或 AI 改坏。解析失败或字段不合法时，整体回退到默认场景并打印警告。
- **数据安全**：假数据只使用虚构的用户名、ID 和金额，禁止从 SIT 或生产环境复制真实数据。
- **构建产物**：不注入 `/web/config` 脚本（`src/plugins/html.ts`）；不复制 `functions/`（Cloudflare 生产函数）和 `pwa/`（`vite.config.ts` 的 `closeBundle`）；不包含埋点 ID。
- **仓库卫生**：删除基线中误提交的个人配置 `.claude/settings.local.json`。
- **访问控制**：保留 `noindex`；是否限制访问由运维决定（见 D3）。
