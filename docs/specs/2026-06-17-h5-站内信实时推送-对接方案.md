# H5 站内信实时推送 · 对接方案（v1，落地版）

- 端：H5 会员前端（`ar_v2_vue_copy`，Vue3 + Pinia + Vant4，多 entrance 多皮肤）
- 后端：`Ar_V1_LotteryApi`；通道：AWS AppSync Events API；后端文档 v3（连接信息并入登录返回）
- 连接内核参考：`ar_sass_tenant/src/store/modules/adminWs.ts`
- 设计稿（Figma `Ignj7NWniLd6MW9bdvQske`）：
  - B 系（顶部横幅/通知中心）：到账 `9790-57945` · 待领取 `9790-57960` · 多条 `9790-62350`
  - C 系（居中模态）：二次验证 `9577-52723` · KYC中断 `9577-52751` · 提现退回 `9577-52779`

---

## 一、目标
登录后连接订阅本人频道 → 收到推送按 `pushStyle` 实时展示 → 点击按 `jumpAction` 跳转。标题/正文已由后端按会员语言渲染好，前端直接展示。

## 二、关键决策（均已确认）
1. **连接层**：精简移植 `adminWs.ts` 内核，剥离全部后台业务；新增 `aws-amplify@^6.16.3`。**单 store**（`useNotifyWsStore`：连接状态 + 通知列表合一）。
2. **UI 全部复用 `DialogQueue`（不自建 host）**：C 系（C3/C4）= 居中模态队列项；B 系（到账/待领取/多条）= 给 DialogQueue 扩展的 **`top` 非阻塞**队列项（单项 `NotifyCenterView` 读列表渲染横幅/通知中心）。**UI 1:1 像素还原**（取 Figma `get_design_context` 精确规格）。
3. **范围**：B 系三态 + C 系模态全做，接线 `jumpAction`。**不做**历史回填、不做全局未读角标、不联动 Messages 列表。
4. **续连**：连接信息持久化；刷新重进读缓存重连；Token 临期复用 `RefreshToken`（已确认返回 webSocket 三字段）重连，不复用旧 Token。

## 三、整体架构与数据流
```
登录 signIn() ┐
RefreshToken(axios 拦截器) ├─ 读 LoginData.webSocketUrl/webSocketChannels/webSocketTokenExpireAt
AllPageDialog 冷启动        ┘
        ▼  notifyWs.bootstrap(...) + connect()
  notifyWs.ts（单文件 + 单 store）
   parseWebSocketUrl → configureAppSync(oidc, decodeJWT) → events.connect(channels[0])
   → subscribe(next/error) → make-before-break 重连 + scheduleRefresh(到期前3min)
        ▼ next → parsePushEvent → messageHandler = dispatchPush
  dispatchPush(data)
        ├── C 系(C3/C4 或 templateId 11/12) → DialogQueue.push(NotifyCModal·key, presentation:center, priority:1000)
        │        → DialogQueueHost 居中模态渲染（既有遮罩/ESC/滚动锁）
        └── 其余(B 系) → store.add(data) + 确保 NotifyCenterView 队列项在队(presentation:top, priority:0)
                 → DialogQueueHost('top' 非阻塞) → NotifyCenterView：0→出队 / 1→NotifyBanner / ≥2→NotifyCenterList
        ▼ 点击/按钮 → jumpBy(jumpAction, activityCode)
```
- **复用而非新建**：B/C 都是 DialogQueue 队列项，经 priority 串行（C=1000 抢占，B=0）；仅给 host 扩了一个 `top` 非阻塞形态。
- 内核**零 `.vue` 依赖**：组件在 UI 层用 registry 按 key 注册，dispatch 只按 key 入队（避免 store↔组件循环）。

## 五、连接内核 `src/stores/modules/notifyWs.ts`（单文件 + 单 store）
分段：① 契约（§4/§5 + `parsePushEvent`）② AppSync 适配器（`parseWebSocketUrl`/`configureAppSync` oidc/`connectAppSyncChannel`，region 默认 `ap-south-1`）③ `jumpBy`（路由映射）④ **`useNotifyWsStore`**（连接：make-before-break + scheduleRefresh + 持久化；通知列表：去重/本地 receivedAt/单条自动消失/聚合）⑤ `dispatchPush` + `setupNotifyWs` + key 常量。
单频道（只订 `channels[0]`，频道后端预拼）；空 `webSocketUrl` → 不连接（降级，§2.2）。

## 六、消息契约与分发
- 守卫 `businessType==='UserTemplateNotify'`（§7.5）；`data{templateId,activityCode,title,message,jumpAction,pushStyle}`。
- `dispatchPush`：C 系 → `createDialogQueueItem(NOTIFY_C_MODAL_KEY)`（center, priority 1000）；其余 → `store.add` + 确保 `NOTIFY_CENTER_KEY`（top, priority 0）在队。
- 去重（§7.3）：`add` 内同 `(templateId,activityCode,message)` 短窗口去重。

## 八、登录接入 / 持久化 / 续连
- **登录**：`stores/modules/user.ts → signIn()`（getUserInfo 后）补读 `res.data` 三字段 → `notifyWs.bootstrap+connect`；空 url 不连。
- **持久化**：localStorage（`ar_ws_url/ar_ws_channels/ar_ws_token_expire_at`）。
- **冷启动重连**：`AllPageDialog.vue → setupNotifyPush()`（onMounted）→ 注册 NotifyCModal/NotifyCenterView、注入 refresher、`setupNotifyWs()`、有 token 且缓存 url 未过期则 connect。
- **续连**：`axios.ts` 刷新 token 成功后把响应三字段喂 `notifyWs.applySubscription`；proactive 定时器经注入 `wsRefresher`（axios 导出，调 `RefreshToken`）重连（不复用旧 Token）。
- **登出**：`loginout()` 调 `notifyWs.reset()`（断连 + 清缓存 + 清列表）。

## 九、jumpAction 路由映射（核对自现有 router.push）
`none`→不跳 · `wallet`→`{name:'wallet'}` · `withdraw`→`{name:'Withdraw'}`(大写W) · `activity`→`{name:'activity'}`。`jumpBy` 收敛于 notifyWs.ts，activityCode 透传 query。
