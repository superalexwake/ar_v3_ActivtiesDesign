## 0. 目的、目标与非目标

**问题**：控制台只有全局开关（登录、奖励状态四选一、8 个活动开关、延迟、语言）。产品要看某个活动的具体状态（签到第 6 天、周卡今日已领、转盘必中 iPhone、回归奖励只剩 30 秒），只能改代码。

**目标（可观测）**

| 编号 | 目标 | 验收方式 |
|---|---|---|
| C1 | 控制台三栏：左清单、中手机、右“当前活动”控制面板；全局设置在顶部工具栏 | 1440×900、1280×800 下三栏同时可见，手机 iframe 视口仍为 375×812 |
| C2 | 每个有控制项的清单项都有自己的面板：边界场景、参数、动作 | 第 3 节列出的 33 个清单项点开后面板内容与本文一致 |
| C3 | 控制项只在 `catalog.json` 声明，控制台按声明渲染 | 在 `catalog.json` 给某活动加一个参数、在其 handler 读它，不改 `console.html` 即可在面板出现并生效 |
| C4 | 参数决定 handler 输出 | 每个边界场景点一次，手机里出现第 3 节“预期”列描述的画面，浏览器控制台无未捕获异常，也没有 `[mock] 未覆盖:` 警告 |
| C5 | 倒计时参数刷新不重置 | 应用“剩 30 秒”后刷新手机页，倒计时从刷新前的剩余时间继续 |

**非目标**：不改 `src/` 业务代码；不做参数的历史记录、导入导出、多人共享；不给入口页“推广”“我的”单独做参数（它们的入口显隐由对应活动的开关控制）；不给独立 HTML 原型提供参数面板。

**约束（沿用）**：handler 只改 `ctx.state`，功能数据用 `featureState()`；用户可见假数据文案用 `pick(ctx, zh, en, hd)`；mock 只导入第三方库、mock 自身文件、`@/api/url`、`import type`；活动开关编码沿用 AGENTS.md 规则 12。

## 1. 数据模型

### 1.1 `catalog.json` 结构扩展

清单项增加 `activity` 字段，文件顶层增加 `activities`（活动 ID → 控制项声明）。多个清单项可以指向同一个活动（如 Type 29/30 都指向 `vip`），它们显示同一块面板、共用同一份参数。

```ts
/** 参数取值 */
type ParamValue = boolean | number | string

/** 参数类型；countdown 是“从应用时刻起算的剩余秒数” */
type ParamType = 'boolean' | 'number' | 'select' | 'countdown'

/** select 的一个选项 */
interface ParamOption {
	/** 选项值，同一参数内唯一；handler 按它分支 */
	value: string
	/** 控制台显示文字 */
	label: string
}

/** 一个可调参数 */
interface ParamDef {
	/** 参数名，/^[a-z][A-Za-z0-9]{0,31}$/，同一活动内唯一；活动开关一律叫 enabled */
	name: string
	/** 控制台显示名（中文） */
	label: string
	/** 参数类型 */
	type: ParamType
	/** 默认值：boolean→布尔；number→有限数；select→某个 options[].value；countdown→秒数（非负整数，0 表示关闭） */
	default: ParamValue
	/** 仅 select 必填：至少 2 项 */
	options?: ParamOption[]
	/** 仅 number / countdown：闭区间下限，缺省 0 */
	min?: number
	/** 仅 number / countdown：闭区间上限，缺省 999999999 */
	max?: number
	/** 仅 number：输入步长，缺省 1；金额写 0.01 */
	step?: number
	/** 仅展示：单位，如 ₹、%、天、次、人、张 */
	unit?: string
	/** 仅展示：驱动的接口字段，如 "GetTaskList.efficientPeople"，面板以灰字显示在控件下方 */
	drives?: string
}

/** 边界场景：一键设置多个参数，然后打开页面或弹窗 */
interface PresetDef {
	/** 按钮文字，同一活动内唯一 */
	label: string
	/** 与默认值不同的参数；没写的参数取默认值（不是保留当前值）；countdown 写秒数 */
	values: Record<string, ParamValue>
	/** 预期画面，一句话，显示在按钮下方 */
	note?: string
	/** 应用后打开的 H5 路由（可带查询串）；与 popup 互斥；都不写时按当前清单项的默认方式打开 */
	route?: string
	/** 应用后触发的首页弹窗 */
	popup?: PopupKey
}

/** 动作：不改参数，只打开页面或弹窗 */
interface ActionDef {
	/** 按钮文字 */
	label: string
	/** H5 路由；与 popup 二选一 */
	route?: string
	/** 首页弹窗键；与 route 二选一 */
	popup?: PopupKey
}

/** 一个活动的控制项声明 */
interface ActivityControls {
	/** 面板顶部说明，1～2 句 */
	note?: string
	/** 参数，按面板显示顺序排列 */
	params: ParamDef[]
	/** 边界场景 */
	presets?: PresetDef[]
	/** 动作 */
	actions?: ActionDef[]
}

/** 清单项（在原有字段上增加 activity） */
interface CatalogItem {
	title: string
	type?: number
	kind: 'route' | 'popup' | 'html' | 'none'
	target?: string
	popup?: PopupKey
	note?: string
	/** 控制项所属活动 ID，即 Catalog.activities 的键；没有控制项的项不写 */
	activity?: string
}

/** 控制台清单 */
interface Catalog {
	groups: { title: string; items: CatalogItem[] }[]
	/** 活动 ID（/^[a-z][A-Za-z0-9]{0,31}$/）→ 控制项声明 */
	activities: Record<string, ActivityControls>
}
```

**校验规则**（控制台加载 `catalog.json` 时执行；H5 端只做 1.3 节的取值校验）：

| 对象 | 规则 | 不满足时 |
|---|---|---|
| `CatalogItem.activity` | 必须是 `activities` 的键 | 该项仍可打开；面板显示“控制项声明缺失：<id>” |
| `ParamDef.name` | 符合正则、活动内唯一 | 整个活动的面板改为显示错误清单，不渲染控件 |
| `ParamDef.default` | 类型与 `type` 一致；select 在 options 内；number/countdown 在 [min, max] 内；countdown 为非负整数 | 同上 |
| `ParamDef.options` | 仅 select 且 ≥2 项、value 唯一 | 同上 |
| `PresetDef.values` | 键都是已声明参数，值通过与 default 相同的校验 | 同上 |
| `PresetDef` / `ActionDef` | `route`、`popup` 至多一个（动作必须恰好一个）；`popup` 是合法 `PopupKey`；`route` 以 `/` 开头 | 同上 |

同一活动被多个清单项引用时只校验一次；错误清单写明“活动 ID · 参数/场景名 · 原因”，产品或 AI 据此改 `catalog.json`。

### 1.2 场景存储

```ts
/** 演示场景，控制台写入 localStorage['proto:scenario']，H5 启动时读取一次 */
export interface Scenario {
	/** 是否已登录 */
	loggedIn: boolean
	/** 本次启动要触发的首页弹窗；null 表示不触发 */
	popup: PopupKey | null
	/** 每个接口的模拟延迟（毫秒） */
	latencyMs: number
	/** 各活动参数的覆盖值，键为活动 ID；只有在控制台应用过的活动才有条目。countdown 存截止时刻的毫秒时间戳，0 表示关闭 */
	activities: Record<string, Record<string, ParamValue>>
	/** 最近一次从控制台打开的清单项所属活动 ID；没有时为 null。只用于每日任务页选默认 Tab（见 3.2 dailyTask） */
	focus: string | null
}
```

- 默认场景：`{ loggedIn: true, popup: null, latencyMs: 200, activities: {}, focus: null }`。
- `switches`、`rewardState` 两个字段删除。`readScenario()` 的校验改为：`activities` 是普通对象、其值也是普通对象、叶子值是布尔/有限数/字符串；`focus` 是字符串或 null。旧结构（含 `switches`/`rewardState`、缺 `activities`）不通过校验，整体回退默认场景并打印警告，不做迁移。
- `SessionState` 增加 `anchors: Record<string, number>`：键为 `<活动ID>.<参数名>`，值为倒计时截止时刻（毫秒）。只用于“从未应用过的 countdown 参数”，见 1.4。

### 1.3 H5 端：读取 catalog、解析参数、handler 读取接口

H5 与控制台读同一个 `catalog.json`，默认值只写在这一处。

`mock/index.ts` 安装顺序不变（adapter → 停用 Service Worker → 登录态），只在“写登录态”之前等待一次清单：

```ts
const scenario = readScenario()
const state = readState()
const ready = loadParams(scenario, state) // fetch('catalog.json', { cache: 'no-store' }) → resolveParams()
window.__protoMock = { unhandled: [], scenario, defaultScenario: DEFAULT_SCENARIO, params: {} }
axios.defaults.adapter = createMockAdapter(routes, scenario, state, ready) // 每个请求先 await ready
disableServiceWorker()
window.__protoMock.params = await ready // 顶层 await：main.ts 在它完成后才创建 App 和 store
writeState(state)
applySession()                           // userInfo 种子改用 session.ts 导出的 userInfoOf(ctx)，与 GetUserInfo 同源
```

- 顶层 await 只推迟 `main.ts` 的函数体（createApp、store 读 localStorage），adapter 在 await 之前已经装好，假设 A1 不受影响。Vite 7 默认构建目标支持顶层 await，不改构建配置。
- `catalog.json` 加载或解析失败：`console.error('[mock] catalog.json 加载失败：…')`，按空清单处理；此时读取参数的 handler 返回 `code -1`（见下），控制台本身也会提示“清单加载失败”。

```ts
/**
 * 把场景覆盖值与 catalog.json 默认值合并成每个活动的有效参数。
 *
 * @param defs - catalog.json 的 activities。
 * @param scenario - 本次启动的场景。
 * @param state - 会话状态；为从未应用过的 countdown 参数写入 anchors。
 * @returns 活动 ID → 参数名 → 有效值。countdown 为截止时刻毫秒时间戳，0 表示关闭。
 */
export function resolveParams(
	defs: Record<string, ActivityControls>,
	scenario: Scenario,
	state: SessionState
): Record<string, Record<string, ParamValue>>

/**
 * 读取某个活动当前生效的参数。
 *
 * @typeParam T - 该活动的参数类型，由各 handlers 文件按 catalog.json 声明自行定义。
 * @param ctx - 请求上下文。
 * @param activity - 活动 ID。
 * @returns 已校验、已补默认值的参数（只读）。
 * @throws 活动未在 catalog.json 声明时抛错；adapter 转成 `code -1` 并打印接口路径。
 */
export function params<T>(ctx: MockContext, activity: string): Readonly<T>
```

- 两个函数放在 `mock/scenario.ts`；`MockContext` 增加 `params: Record<string, Record<string, ParamValue>>`，由 adapter 注入；`ProtoMockInfo` 增加同名 `params` 供控制台显示实时值。
- 取值校验（`resolveParams` 内）：boolean 必须是布尔；number 必须是 [min, max] 内的有限数；select 必须是 options 之一；countdown 必须是 ≥0 的有限数。不合法的覆盖值忽略、取默认值，并 `console.warn('[mock] 参数不合法，已用默认值：<活动>.<参数>')`。
- handler 用法（每个文件按声明定义自己的参数类型）：

```ts
interface SignInParams { signedDays: number; todaySigned: boolean; scheme: 'normal' | 'big' }
const p = params<SignInParams>(ctx, 'signIn')
```

### 1.4 倒计时参数

- 控制台里填“剩余秒数”（显示为 `HH:MM:SS` 输入框）；**应用时**换算为截止时刻 `Date.now() + 秒数 × 1000` 写进 `scenario.activities[id][name]`。场景在 localStorage 里，刷新、重开手机页都从同一截止时刻继续走；“重置数据”会清掉它。
- 从未应用过的活动：`resolveParams` 用 `state.anchors['<活动>.<参数>'] ??= Date.now() + 默认秒数 × 1000`，在本标签页会话内保持不变；“重置数据”清会话后重新起算。
- `0` 表示“关闭”：解析结果就是 `0`，含义由 handler 决定（第 3 节逐项写明，如“按当天 0 点”“不下发”）。
- handler 拿到的一律是截止时刻（毫秒），自己换算成接口需要的格式：`YYYY-MM-DD HH:mm:ss` 字符串、毫秒时间戳或“距今秒数”，并按页面要求在信封顶层返回 `serviceNowTime`。截止时刻已过时，handler 返回“已结束”的数据，不能继续返回会让页面反复重拉的数据（每项的结束态见第 3 节）。
- 面板显示：countdown 控件旁实时显示剩余时间（每秒刷新，取 `h5().__protoMock.params` 的截止时刻计算）；为 0 时显示“未启用”。

### 1.5 应用流程（写场景 → 重载手机）

控制台只有一个写入口 `applyAndOpen(change, open)`，清单点击、改参数、点边界场景、点动作、重置都走它：

1. **卸载**：`phone.src = 'about:blank'`，**等待它的 `load` 事件**后再继续。不能连续同步赋值两次 `src`：从 `index.html#/a` 赋成 `about:blank` 再立刻赋成 `index.html#/b` 时，浏览器只把它当作同文档的 hash 变化，H5 不会重新启动，旧文档的 adapter 还会把旧会话写回 sessionStorage。
2. **写场景**（localStorage `proto:scenario`）：
   - 改参数：`activities[id] = { ...当前有效值, [name]: 新值 }`；当前有效值优先取 `h5().__protoMock.params[id]`（含倒计时截止时刻），手机没在跑 H5 时取场景值，再没有取默认值。
   - 边界场景：`activities[id] = { ...默认值, ...preset.values }`（未写的参数回到默认值），countdown 秒数换算成截止时刻。
   - “恢复默认”：`activities[id] = 默认值`（countdown 按应用时刻重新起算）。
   - `focus` = 当前清单项的 `activity`（没有时 null）。
   - 打开方式是弹窗时 `popup = 弹窗键`、`loggedIn = true`；否则 `popup = null`。
3. **清该活动的会话数据**（sessionStorage `proto:state`；在改参数、边界场景、恢复默认时做，打开方式是弹窗时也做——包括清单里的弹窗项、“弹出弹窗”动作和带 `popup` 的边界场景，这样领过的弹窗每次都能再弹出来）：删除 `features[id]`、`claimed` 中以 `<id>:` 开头的键、`anchors` 中以 `<id>.` 开头的键。handler 约定（第 4 节每个任务都要遵守）：功能数据的 `featureState` 键等于活动 ID，领取键以 `<活动ID>:` 开头，初始值从参数生成。钱包余额 `balance` 是全局的，不清。
4. **清 H5 自己的弹窗标记**（每次打开都做）：localStorage `dialog:firstSave`（首充“今日不再提示”）、sessionStorage `pop_prompt`（公告已弹）、`pop_laundry`（大奖提示已弹）。否则勾过“今日不再”的首充弹窗当天再也弹不出来，公告、大奖提示在同一会话里也只能看到一次。这些弹窗是否出现仍由场景与参数决定，清标记不会让没开启的弹窗冒出来。
5. **加载**：`phone.src = 'index.html#' + 路由`；弹窗路由为 `/`。改参数时路由取手机当前 hash（含查询串），手机不在 H5 时取当前清单项的 `target`。
6. **重置数据**：卸载 → 删除 `proto:state` → 场景写回默认 → 执行第 4 步 → 加载 `index.html#/`。

清单点击也走这条路径（写 `focus` 并整页重载），不再用改 hash 的方式切页。代价是每次切换多一次 H5 启动（本地约 0.5～1 秒），换来每次打开都是按当前场景新启动的页面，也让每日任务页的 4 个清单项能落在各自的 Tab 上。

### 1.7 失败信封

`envelope.ts` 的 `fail` 扩展为：

```ts
/**
 * 构造业务失败信封。
 *
 * @param msg - 展示给用户的文案（handler 传 pick() 结果）。
 * @param extra - msgCode：页面按它查语言包或分流弹窗；data：失败时附带的数据；
 *   code：默认 -2（拦截器 reject，AwaitApiResult 弹 toast）；只有页面自己 await 接口且只处理 resolve 分支时用 1。
 * @returns 失败信封。
 */
export const fail = (msg: string, extra: { msgCode?: number; data?: unknown; code?: -2 | 1 } = {}): MockEnvelope
```

必须用 `code: 1` 的接口（页面没有 try/catch，`-2` 会变成未捕获的 Promise 拒绝）：大转盘 `GetTurnTableDraw`（`useTurntable.hook.ts:114-130`）、红包兑换 `ConversionRedpage`（`RedeemGift/index.vue:153-160`）。周卡月卡的 `failEnvelope` 改用此函数。
